# ガチャガチャアプリ

VSコードで動かせる、アカウント・ポイント・ショップ・チケット・収益機能付きのガチャガチャWebアプリです。

## できること

- **確率設定**: ガチャの中身（アイテム）ごとに 0.01% 刻みで排出確率を設定できます（合計は必ず100.00%）
- **中身**: 1つのガチャにつき最大100種類のアイテムをテキストで登録できます
- **アカウント**: ユーザー登録・ログイン機能。**最初に登録した人が自動的に管理者になります**
- **ポイント**: 新規登録時に100pt付与。ガチャごとに消費ポイントを設定可能
- **ガチャの種類**: 通常ガチャと「チケットガチャ」の2種類。チケットガチャで当たると、結果が「マイチケット」に特典チケットとして追加されます
- **チケット(ガチャ引換券)**: 管理画面から、特定のガチャのチケットを全ユーザーへ一括配布、または個別のユーザーへ配布できます。チケットを持っていればポイントを消費せずに引けます
- **ショップ**: 管理画面でショップを作成でき、1ショップにつき商品を最大50個まで登録できます。商品ごとに「購入したらアイテムに入る/マイチケットに入る」を選べます
- **アイテム / マイチケット**: 「アイテム」は手元に残るコレクション、「マイチケット」はマッサージ券・お手伝い券など、実際に使ったら「使用済み」にできる特典です
- **収益**: ショップごとに「収益ON/OFF」を設定でき、ONのショップで商品が買われると管理者の収益に加算されます。月が変わると自動的に前月分が履歴に記録され、今月分は700ptにリセットされます

※ メール通知機能は今回のバージョンには含まれていません（必要になったら追加できます）。

## セットアップ方法（VS Code）

1. このフォルダをVS Codeで開く
2. ターミナルを開いて、依存パッケージをインストール
   ```
   npm install
   ```
3. サーバーを起動
   ```
   npm start
   ```
4. ブラウザで `http://localhost:3000` を開く

## 使い方

1. 最初にアカウントを1つ登録する（このアカウントが管理者になります）
2. 右上の「管理画面」から、ガチャを作成する
   - ガチャ名、種類（通常/チケット）、1回あたりの消費ポイントを入力
   - 「＋ 中身を追加」でアイテム名と確率(%)を入力していく（合計が100.00%になっているか画面下に表示されます）
   - 「保存する」で作成完了
3. 同じく管理画面の「ショップ管理」から、ショップと商品（最大50個）を作成する。商品ごとに「アイテムに追加/マイチケットに追加」を選べる。収益として記録したい場合はチェックを入れる
4. ユーザー画面に戻ると、作成したガチャ・ショップが表示されます
5. 管理画面の「チケット配布」タブから、ガチャチケットを全ユーザーや特定ユーザーに配れます
6. 「ユーザー・ポイント」タブから、任意のユーザーにポイントを付与できます
7. 「収益」タブで、収益ONのショップから積み上がった今月の収益と、過去の月別履歴を確認できます

## データの保存場所

`data/users.json`・`data/gachas.json`・`data/shops.json`・`data/revenue.json` に保存されます（サーバー初回起動時に自動作成）。バックアップしたい場合はこれらのファイルをコピーしてください。

## Renderなど無料ホスティングへの公開

GitHubにこのプロジェクトを公開し、Render（無料プランあり・クレジットカード登録不要）でWeb Serviceとして次の設定でデプロイすると、家族それぞれが自分のスマホ・パソコンから同じURL・同じアカウントでログインできるようになります。

- Environment: Node
- Build Command: `npm install`
- Start Command: `npm start`
- Instance Type: Free

**注意**: Renderの無料プランはディスクが永続化されないため、サービスが再起動されるとdataフォルダの内容（ユーザー・ポイントなど）が消えてしまうことがあります。長く使う場合は、定期的にdataフォルダをバックアップするか、有料プランや外部データベースへの移行を検討してください。

## 今後拡張したい場合のヒント

- メール通知を追加する場合: `server.js` の `/api/gachas/:id/play` 内、結果を返す直前に、ユーザーがメールアドレスを登録していればメール送信APIを呼び出す処理を追加してください（Nodemailer + Gmailアプリパスワード等が手軽です）
- 本格運用する場合は `data/*.json` の代わりにSQLite等のデータベースへの置き換えをおすすめします
